# panel-note

用户要的是一份**他和 agent 轮流编辑**的 md：agent 写进去的，用户能在右栏直接看到、直接改；用户改过的，agent 下一轮读得到。

## 文件放哪

- 默认 `<workspace>/NOTES.md`。
- 面板只能打开**工作区里**的文件：`dsh-better-sidebar` 有 workspace fence，编辑器页只认工作区路径；`dsh-marktext` 也是从侧栏文件树点开。写到 `$HOME`、`/tmp`、工作区外，用户根本看不到。
- 工作区里已有 `NOTES.md` 就复用它，不新建平行文件。
- 需要按主题分开时用 `notes/<主题>.md`，主题小写短横线，例如 `notes/deploy.md`。
- 同一工作区里有多个 bot 时，各写 `notes/<bot 名>.md`，不要抢同一份文件。
- agent 打不开用户的面板，**别声称「我已经帮你打开了」**。给相对路径，让用户自己在右栏点开一次，之后那个 tab 会跟着会话留着。
- `dsh-better-sidebar` 的编辑器 tab 按会话保存布局：用户在这个会话里开过一次 `NOTES.md`，切走再回来还在。
- 装了 `@fstack/dsh-panel-entry` 时，右侧栏有一条 `Panel` 入口，点它就打开 `NOTES.md`，可以直接让用户点这个。

## 怎么写

追加，不重写。

1. 先 `read` 文件；不存在就用 `write` 建一个只有一级标题的骨架。
2. 用 `edit` 在末尾追加**一条**。不要 `write` 整篇覆盖，不要重排已有段落，不要动用户写的行。
3. 每条固定形状：

```md
## <一句话标题>

<YYYY-MM-DD HH:MM> · bot

<2–5 句正文。结论先行；细节只有在确实需要时才用列表。>
```

- 一条一件事。同一件事有新进展，就在原小节末尾补一行 `更新（HH:MM）：…`，不新开一节。
- 先搜标题，已经在文件里的内容不要写第二遍。
- 用户点名要写才写。聊天流水账、工具原始输出、整段代码不要搬进去。

## 写完怎么报

- 聊天里一句话：`已写入 NOTES.md → §<标题>`。不贴全文，不复述内容。
- 面板不会实时刷新别人的写入：`dsh-better-sidebar` 的编辑器要重开文件、或保存时走冲突条的 Reload from disk；`dsh-marktext` 同理。用户可能正看着旧版本，所以报一句「面板里重开一下」有用。
- 用户没说要细节时，一句话就够了。

## 什么时候读

- 用户说「看下笔记」「笔记里那条结论」时，`read` 整份再答。
- 新会话第一次涉及这个工作区、且文件存在时，读一次当背景；不要每轮都读。
- 用户改过的行代表用户的意思，**不要回滚**。要改用户写的小节，先问一句。

## 并发与冲突

- 用户可能正开着面板改同一份文件。agent 侧的安全做法只有一条：**read → edit**，让 `edit` 基于当前内容匹配；匹配不到就重新 `read`，不要退化成整篇覆盖。
- 面板侧有版本守卫：`dsh-better-sidebar` 用 `expectedMtimeMs`，`dsh-marktext` 用 `replaceIfVersion`；用户保存时如果文件被 agent 改过，会弹冲突条（Reload from disk），不会静默吞掉任何一边。
- 别在用户可能正在输入时连发多条追加。一条写完就停。

## 不要做

- 不造 `TODO.md`、`最终版.md`、`v2.md` 这类平行文件；同一份笔记往下写。
- 不把面板笔记当记忆库（那是 memory 的事），也不当任务清单（那是 todo 的事）。
- 不往笔记里写密钥、token、带用户名的完整路径。
