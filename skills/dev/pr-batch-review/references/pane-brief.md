# pane brief 模板

herdr 的 `send` 只收单行文本，所以 brief 要压成一行。下面按顺序写，缺一段就等于少一个约束。

## 一行版

```text
仓库 <worktree 路径>（detached 在 PR 头，不要建分支）。只读验证，不要提交、不要 push、不要改作者分支。PR #<n>《<标题>》，对应 issue #<m>：<issue 要求的一句话，含 non-goals>。请验证：<具体行为，一句话>。验收：<命令或截图步骤>。预算 30 分钟，超时写“未完成”并停。输出：结论一句 + findings 列表（文件:行、严重度 P0/P1/P2、是否阻塞）+ 没验证的部分。不确定的标“未确认”。
```

## 每一段为什么在

| 段 | 作用 |
|---|---|
| 仓库与分支 | 防止 agent 在错目录里改到主 checkout |
| 只读 + 三条禁令 | 验证不是交付，改动要留在 worktree |
| PR 标题与 issue 要求 | 给它 spec，不然它会照 PR 描述自证 |
| 要验证的行为 | 一次只验一件事，避免全量回归 |
| 验收动作 | 命令或截图步骤，不写「跑一下测试」 |
| 预算 | 到点停，防止长 e2e |
| 输出格式 | 汇总时能直接抄，不用二次整理 |

## 反面例子

```text
检查一下这个 PR 的逻辑，跑点测试看看有没有问题
```

没有范围、没有验收、没有预算、没有输出格式。pane 里的 agent 只能自己发明标准。

## 多个 PR 并行时

- 一个 PR 一个 pane，pane 名用 `pr-<n>`，便于对照。
- worktree 目录名用 `<repo>-pr-<n>`（worktrunk 建树用 `<repo>.pr-<n>`），不要用分支名——并行几个之后只看目录名要能认出是哪个 PR。
- 4 个一批；每批回来先汇总，再开下一批。
- 同一个仓库的多个 PR 各自开 worktree，不共用目录。
