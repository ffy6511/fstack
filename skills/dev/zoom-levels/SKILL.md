# zoom-levels

本 skill 规定一种分层回复格式，目标是让读者在一次阅读中获得结论与全貌：先读总述段取得结论，再读各分点的首句取得全貌，需要细节时再逐层向下阅读。以下规则均服务于这一目标，仅在用户显式要求时适用。

## 一、结构

1. **总述段**：位于回复开头，2 至 3 句，给出结论、判断或下一步。总述只提供全貌，不展开细节；读者仅阅读此段即可作出判断。超过 3 句，说明细节进入了总述。
2. **正文分点**：按内容分组，每个分点由首句总结与子点构成。分点最多两层，需要第三层时改用完整句子陈述。

## 二、首句的判定标准

每个分点的首句必须同时满足两个条件：

1. 脱离其下子点单独阅读，仍是一句完整且携带信息的陈述。
2. 能够概括其下全部子点的内容。

仅标注话题的名词短语不合格。这类写法只说明该分点讨论什么，不提供任何结论。

| 判定   | 示例                                                         | 说明                             |
| ------ | ------------------------------------------------------------ | -------------------------------- |
| 不合格 | `与现有约定的关系`                                           | 仅标注话题，读者无法从中获得信息 |
| 合格   | `它只约束版面，与 writing-style、ste 各管一段，三者不冲突。` | 单句即给出结论                   |
| 不合格 | `触发方式`                                                   | 名词短语，不含信息               |
| 合格   | `默认不改变现有输出，仅在用户点名时切换为本格式。`           | 单句即给出规则                   |

自检方法：将第一层各分点的首句依次连读。若可独立成篇，格式成立；若语义断裂，说明其中某句退化成了话题标签。

## 三、完整示例

问题：这个 PR 能否直接合并。合格回复示例：

```text
可以先合，但合并前要补一条针对空列表的测试。其余改动没有风险，回滚也简单。

1. **改动范围集中在一个组件，没有触及共享状态。**
   - 只改了 selection-card.tsx 的渲染分支
   - 没有新增依赖，构建产物大小基本不变
2. **唯一的风险是空列表分支，目前没有测试覆盖。**
   - 该分支在旧代码里同样没有测试，属于既有缺口
   - 建议先补一条单测，再合并
3. **回滚成本低，出问题可以单文件还原。**
   - 改动不涉及数据迁移或配置变更
```

只读第一层首句（改动范围、风险、回滚成本），即可得到完整结论；第 2 点的细节按需向下阅读。

不合格示例。同样的内容，只列出话题：

```text
1. 改动范围
2. 风险
3. 回滚
```

读者读完这三行，无法判断这次改动能否合并。

## 四、例外

- 回答只有一两句话，或只有一个步骤：直接陈述，不必为凑结构制造分点。
- 用户要求连贯叙述（解释因果、讲清推理过程）：段落比列表清楚，可以破例。
- 用户表示「不要分点」「正常写」：立即退回段落，不解释理由。

## 五、与其他写作约定的分工

本 skill 只约束版面层次，不涉及用词。`writing-style` 约束词语与句式，`ste` 约束短句与信息顺序，三者各管一段；与用户当前要求冲突时，以用户要求为准。
